## Abstract

We developed AutoscanJ, a suite of ImageJ scripts enabling to image targets of interest by automatically driving a motorized microscope at the corresponding locations. For live samples, our software can sequentially detect biological events from their onset and further image them at high resolution, an action that would be impractical by user operation. For fixed samples, the software can dramatically reduce the amount of data acquired and the acquisition duration in situations where statistically few targets of interest are observed per field of view. AutoScanJ is compatible with motorized fluorescence microscopes controlled by Leica LAS AF/X or Micro-Manager. The software is straightforward to set up and new custom image analysis workflows to detect targets of interest can be simply implemented and shared with minimal efforts as independent ImageJ macro functions.

## Smart microscopy principle

AutoScanJ is a **survey-then-zoom closed-loop controller written in ImageJ macros**. A low-resolution *primary scan* is acquired (either as a continuous tiled mosaic or as a regular grid of "blocks"); an ImageJ macro analyses each tile in real time and returns target coordinates as an ImageJ multi-point selection; the runtime sends those coordinates back to the acquisition software, which performs a *secondary scan* — a higher-resolution, optionally multi-channel / time-resolved capture — at every hit. For live samples the primary scan keeps repeating, so events are caught **at their onset** and re-imaged at high resolution; for fixed samples the secondary scan harvests only the rare positive fields, collapsing data volumes by orders of magnitude (the paper's mitotic-cell demo drops 171.4 GB → 1.5 GB).

The novel contribution is **packaging the survey→detect→zoom loop as plug-in macros that run inside Fiji/ImageJ, talking to the acquisition software over a network protocol** — Micro-Manager via its scripting interface, and Leica LAS AF/X via a subset of the Leica CAM protocol. New detectors are added as independent ImageJ macro functions and shared as files, lowering the barrier to closed-loop microscopy for the analysis-tool community that already lives in ImageJ. Conceptually it implements the same online-classifier-driven-acquisition paradigm as [[Papers/Conrad 2011]], but on an ImageJ-macro front-end and with an open client-server architecture that runs against the µManager device layer ([[Papers/Edelstein 2010]]) rather than a vendor-specific plugin.

The five published application scenarios sketch the design space: (1) confocal mitotic-cell harvest from fixed HeLa via DNA-condensation classifier; (2) FISH-based abnormal-spermatozoon screening on widefield; (3) isolated-cell screening on micropatterned CYTOO chips across 144 blocks; (4) live LLC-PK monitoring that catches mitosis from onset over 16 h with zero false positives in the secondary capture; (5) Drosophila neuroblast asymmetric-division tracking in live block mode.

## Implementation on pymmcore-plus

AutoScanJ's primary/secondary scan distinction maps onto two coupled `MDASequence`s with an `on_frame` callback that converts pixel-space detections into world-coordinate targets — the same pattern as Micropilot, just with the detector authored as an ImageJ macro instead of a Python classifier. In a pymmcore-plus codebase the ImageJ macro is replaced by a Python callable; everything else carries over.

```python
from useq import MDAEvent, MDASequence
from src.core.hardware.core import run_events, set_objective
from src.core.workflows.adaptive import pixel_to_world

# --- Primary scan: low-mag tiled mosaic, detector watches every tile ---
primary_seq = MDASequence(
    stage_positions=[{"x": x, "y": y} for (x, y) in tile_grid],
    channels=[{"config": "DNA", "exposure": 20}],
)

hits: list[dict] = []  # world-coordinate targets

def detector_on_frame(img, event, meta=None):
    """Equivalent to an AutoScanJ detection macro: returns a multi-point
    selection of target pixel coordinates, which we lift to world coords."""
    for cell in detect_condensed_chromatin(img):       # user-supplied rule
        wx, wy = pixel_to_world(cell["centroid_px"], event)
        hits.append({"x": wx, "y": wy})

set_objective(core, 10)
run_events(core, list(primary_seq), on_frame=detector_on_frame)

# --- Secondary scan: high-mag follow-up at every hit ---
def secondary_gen():
    for i, h in enumerate(hits):
        for ch in ("DNA", "tubulin", "actin"):
            yield MDAEvent(
                x_pos=h["x"], y_pos=h["y"],
                channel={"config": ch, "exposure": 100},
                index={"p": i},
            )

set_objective(core, 63)
run_events(core, secondary_gen())
```

For the **live** mode (scenario 4), the primary scan is a repeating loop and the secondary scan can fire mid-loop the instant the detector returns a hit — the closed-loop generator pattern in [[Core/Approach/OADA loop]] / [[Core/Concepts/MDA generators]] reproduces this behaviour: the generator polls a shared `hits` queue and yields a high-mag follow-up event whenever a new entry appears, otherwise yielding the next primary tile.

Production hooks in `src/core/`:

- `../../../src/core/workflows/scanning.py` — `scan_and_detect` / `scan_and_detect_mda` produce the AutoScanJ-style primary-scan hit table.
- `../../../src/core/workflows/adaptive.py` — `survey_cells`, `rank_by_feature`, `zoom_and_measure` encode the survey→rank→zoom skeleton; `pixel_to_world` is the coordinate lift that the AutoScanJ runtime performs when sending pixel detections back to the acquisition software as XY targets.
- The dedicated phenotype-triggered protocol module flagged in [[Papers/Conrad 2011]] would also subsume the AutoScanJ ergonomic of "register a detector as an independent function shared by file"; the equivalent on this stack is making the on-frame detector a plain importable Python callable.

Compared to [[Papers/Conrad 2011]]: same survey→detect→zoom paradigm, same online-classifier semantics. AutoScanJ's distinguishing contribution is the **ImageJ-macro front-end and open client-server architecture** — the Fiji/ImageJ analysis ecosystem becomes directly callable as the detection layer, and Micro-Manager (rather than a vendor-specific plugin) is the acquisition back-end, so the system is reproducible on any open microscope running µManager.
