## Abstract

Microscopy image analysis has recently made enormous progress both in terms of accuracy and speed thanks to machine learning methods and improved computational resources. This greatly facilitates the online adaptation of microscopy experimental plans using real-time information of the observed systems and their environments. Applications in which reactiveness is needed are multifarious. Here we report MicroMator, an open and flexible software for defining and driving reactive microscopy experiments. It provides a Python software environment and an extensible set of modules that greatly facilitate the definition of events with triggers and effects interacting with the experiment. We provide a pedagogic example performing dynamic adaptation of fluorescence illumination on bacteria, and demonstrate MicroMator's potential via two challenging case studies in yeast to single-cell control and single-cell recombination, both requiring real-time tracking and light targeting at the single-cell level.

## Smart microscopy principle

MicroMator factors reactive acquisition into **event-condition-action (ECA) rules**: the user declares *events* as pairs of a **trigger** (a predicate on the live data stream — "fluorescence of the third newborn cell exceeds 100 a.u.", "more than 100 cells in the field of view", "at frame 10") and an **effect** (a hardware actuation or a further computation that runs when the predicate fires). The microscope controller is a plain Python process, so triggers and effects can embed arbitrary analysis, machine learning, or external I/O.

The contribution is the **programming model**, not a specific biological detector: by exposing events as first-class Python objects, the framework lets a user compose complex reactive experiments (single-cell optogenetic control, single-cell recombination) out of small declarative rules rather than re-writing a bespoke acquisition loop each time. The same pattern generalises: any closed-loop microscopy experiment can be phrased as one or more ECA rules watching the frame stream.

## Implementation on pymmcore-plus

The ECA pattern maps cleanly onto a useq event generator with an `on_frame` callback. Each event is a `(trigger, effect)` pair; the callback evaluates all triggers against the latest frame and shared state, and effects either mutate the state (picked up by the generator on the next event) or append extra events for the engine to execute (new `MDAEvent`s with different channels, exposures, SLM patterns, XY positions).

```python
from dataclasses import dataclass
from typing import Callable
from useq import MDAEvent, SLMImage
from src.core.hardware.core import run_events

@dataclass
class Event:
    """MicroMator-style event: a trigger predicate + an effect callable."""
    trigger: Callable[[dict], bool]       # state -> fire?
    effect: Callable[[dict, list], None]  # state, extra_events -> mutate

def reactive_acquisition(core, events: list[Event], channel="GFP", max_frames=500):
    state = {"frame_idx": 0, "history": [], "mode": "poll"}
    extra_events: list[MDAEvent] = []

    def on_frame(img, event, meta=None):
        state["frame_idx"] += 1
        state["last_img"] = img
        for ev in events:
            if ev.trigger(state):
                ev.effect(state, extra_events)

    def gen():
        i = 0
        while i < max_frames:
            if extra_events:                 # effect-queued events go first
                yield extra_events.pop(0)
            else:
                yield MDAEvent(channel={"config": channel}, index={"t": i})
                i += 1

    return run_events(core, gen(), on_frame=on_frame)

# --- example: "if mean intensity > 500, switch to low-exposure burst" ---
def bright_trigger(s):  return s["last_img"].mean() > 500 and s["mode"] == "poll"
def burst_effect(s, xs):
    s["mode"] = "burst"
    for _ in range(20):
        xs.append(MDAEvent(channel={"config": "GFP"}, exposure=5))
```

Production hooks in `src/core/`:

- `../../../src/core/hardware/core.py` — `run_events` is the dispatcher that drives the ECA loop.
- [[../../../src/core/workflows/]] — no dedicated ECA module exists yet. A `src/core/workflows/reactive.py` exposing `Event`, `reactive_acquisition`, and a small library of common triggers (`threshold_above`, `count_exceeds`, `at_frame`, `cell_position_changes`) and effects (`switch_channel`, `set_slm_mask`, `queue_zstack`, `move_stage`) would make MicroMator-style composition ergonomic on pymmcore-plus.
- The paper's "event creator + trigger + effect" three-file convention is the same idea as a small DSL on top of `MDAEvent`; keeping the DSL thin (just a pair of Python callables) avoids re-implementing useq's own engine.

Compared to [[Papers/Mahecic 2022]]: Mahecic is one concrete ECA pair (CNN-trigger → burst-rate-effect) baked into an iSIM; MicroMator is the *framework* that lets a user declare that rule — and arbitrarily many others — in Python.
