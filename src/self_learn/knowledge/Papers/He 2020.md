## Abstract

Fluorescence microscopy is an essential tool for biological discoveries. There is a constant demand for better spatial resolution across a larger field of view. Although strides have been made to improve the theoretical resolution and speed of the optical instruments, in mesoscopic samples, image quality is still largely limited by the optical properties of the sample. In Selective Plane Illumination Microscopy (SPIM), the achievable optical performance is hampered by optical degradations encountered in both the illumination and detection. Multi-view imaging, either through sample rotation or additional optical paths, is a popular strategy to improve sample coverage. In this work, we introduce a smart rotation workflow that utilizes on-the-fly image analysis to identify the optimal light sheet imaging orientations. The smart rotation workflow outperforms the conventional approach without additional hardware and achieves a better sample coverage using the same number of angles or less and thereby reduces data volume and phototoxicity.

## Smart microscopy principle

In SPIM, conventional multi-view acquisition rotates the sample to a fixed set of evenly spaced angles (e.g. 4 views at 0/90/180/270°), regardless of whether those angles actually improve coverage for *this* specimen. Smart rotation replaces the fixed rotation schedule with an online decision loop: after each view, an image-quality metric is evaluated on the fly over the acquired stack, the sample geometry and current coverage are updated, and the next rotation angle is chosen to maximise the expected marginal coverage gain. The microscope stops when the coverage budget is reached rather than when a pre-set angle list is exhausted.

The contribution is sample-adaptive view selection: the optimal set of angles depends on the specimen's opacity and shape, which are unknown before the run. By measuring image quality in-loop and feeding it back to the rotation stage, the same coverage is reached with fewer angles, cutting data volume and phototoxicity without adding hardware.

## Implementation on pymmcore-plus

Smart rotation maps onto the adaptive-generator pattern: a generator emits one acquisition event per candidate angle, an `on_frame` callback scores the resulting stack's image quality and updates a shared coverage map, and the generator consults that state to pick the next angle (or terminate). The rotation axis is a `StateDevice` (motorised θ stage) or a `Stage` with angular units, controlled via `core.setPosition(rotation_device, theta)`.

def smart_rotation_acquisition(core, z_plan, channel="GFP"):
    state = {
        "coverage": None,       # running max of per-voxel quality across views
        "visited": set(),       # angles already acquired
        "views": [],            # (theta, stack, quality) tuples
    }

    def on_frame(img, event, meta=None):
        # For a full stack per view, accumulate frames into a 3D array keyed by θ.
        theta = event.metadata["theta"]
        state["views"].append((theta, img, None))

    def next_angle():
        """Pick the unvisited angle that most reduces the uncovered voxel set."""
        if not state["views"]:
            return 0.0
        # Rotate each view's quality map into the common sample frame and take
        # the voxel-wise max; pick the angle whose quality map adds the most
        # new high-quality voxels to that union.
        best, best_gain = None, -np.inf
        for theta in CANDIDATE_ANGLES:
            if theta in state["visited"]:
                continue
            gain = estimate_marginal_coverage(state, theta)  # sample-geometry model
            if gain > best_gain:
                best, best_gain = theta, gain
        return best

    def gen():
        for i in range(MAX_VIEWS):
            theta = next_angle()
            if theta is None or current_coverage(state) >= COVERAGE_TARGET:
                return
            state["visited"].add(theta)
            core.setPosition(ROTATION_DEVICE, float(theta))
            core.waitForDevice(ROTATION_DEVICE)
            for z in z_plan:
                yield MDAEvent(
                    channel={"config": channel},
                    z_pos=float(z),
                    index={"v": i, "z": int(z)},
                    metadata={"theta": float(theta)},
                )

    return run_events(core, gen(), on_frame=on_frame)

This paradigm generalises beyond SPIM: the same closed loop (acquire view → score coverage → pick next view) applies to tomographic / multi-angle setups, to rotating-stage histology, and to multi-objective confocal whenever "which view next" is a live decision rather than a fixed schedule.
